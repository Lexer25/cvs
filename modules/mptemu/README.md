# mptemu — эмулятор внешнего контроллера ворот и табло

Модуль подменяет реальный контроллер MPT и табло: принимает по TCP кадры
протокола Artonit, отвечает корректным кадром и запоминает, что было
приказано воротам и что выведено на табло.

Исходные файлы модуля `ver30` не изменяются: эмулятор подключается как
отдельный модуль и работает «сбоку» от боевой логики.

## Состав

```
modules/mptemu/
  config/mptemu.php                    настройки
  classes/Emulator/Protocol.php        кадры, BCC, коды команд
  classes/Emulator/State.php           состояние в JSON + flock
  classes/Emulator/Server.php          TCP-сервер
  classes/Task/Emulator.php            minion-задача запуска
  classes/Controller/Mptemu.php        веб-панель
  bin/start_mptemu.bat                 запуск двойным щелчком
```

## Включение

В `application/bootstrap.php` в списке `Kohana::modules` должна быть строка:

```php
'mptemu' => MODPATH.'mptemu',
```

Без неё не найдутся ни конфиг, ни классы, ни маршрут панели.

## Запуск

```
C:\xampp\php\php.exe index.php --task=emulator
```

или `bin\start_mptemu.bat`. Параметры:

| параметр | по умолчанию | смысл |
|---|---|---|
| `--host` | `0.0.0.0` | адрес прослушивания |
| `--port` | `8000` | порт (см. ниже) |
| `--reset` | `0` | `--reset=1` обнуляет состояние перед стартом |

Остановка — `Ctrl+C`.

## Перевод ворот на эмулятор

```sql
UPDATE hl_param
   SET box_ip = '127.0.0.1', tablo_ip = '127.0.0.1'
 WHERE id IN (1, 2);
```

Порт можно не менять: `phpMPTtcp::connect()` принудительно ставит `8000`
для TCP, поэтому эмулятор обязан слушать именно этот порт.

Вернуть обратно — те же поля прописать заново реальными адресами.

## Несколько комплектов контроллер + табло

Портами комплекты развести нельзя (клиент всегда идёт на 8000), поэтому
каждый комплект моделируется **своим IP-адресом**. В Windows весь диапазон
`127.0.0.0/8` направлен на loopback, добавлять адреса через `netsh` не нужно.

Один процесс эмулятора обслуживает все комплекты и различает их по адресу
назначения входящего соединения (`stream_socket_get_name($conn, FALSE)`).

| Комплект | `hl_param.box_ip` / `tablo_ip` |
|---|---|
| Ворота 3.2 — въезд (id 2) | `127.0.0.2` |
| Ворота 3.1 — въезд (id 3) | `127.0.0.3` |
| Ворота 3.1 — выезд (id 4) | `127.0.0.4` (табло нет) |
| ... | ... |
| Ворота 2.4.2 — въезд (id 13) | `127.0.0.13` |

```sql
UPDATE hl_param SET box_ip = '127.0.0.2',  tablo_ip = '127.0.0.2'  WHERE id = 2;
UPDATE hl_param SET box_ip = '127.0.0.3',  tablo_ip = '127.0.0.3'  WHERE id = 3;
UPDATE hl_param SET box_ip = '127.0.0.4'                           WHERE id = 4;
COMMIT;
```

У выездных ворот (id 4, 6, 7, 8, 10) в бою `tablo_ip` пустой — табло там
нет, и `phpTablo` сам отключается. Если нужно проверить и вывод на табло,
пропишите им адрес эмулятора тоже.

Вернуть обратно можно ровно теми значениями, что были до правки — их
стоит сохранить отдельным `SELECT` перед `UPDATE`.

Имена комплектов для панели и консоли задаются в конфиге:

```php
'aliases' => array(
	'127.0.0.2' => 'Ворота 2 — въезд',
	'127.0.0.3' => 'Ворота 3 — выезд',
),
```

В консоли каждая строка получает префикс комплекта:

```
22:31:07 [Ворота 2 — въезд] подключение от 127.0.0.1:53012
22:31:07 [Ворота 2 — въезд] OPEN DOOR 1
22:31:08 [Ворота 3 — выезд] OPEN DOOR 0
```

На панели каждый комплект — отдельный блок со своими воротами, табло,
режимом имитации и историей команд. Режим сбоя включается **по комплекту**,
остальные продолжают работать нормально.

## Наблюдение

### Консоль

```
22:10:03 слушаю tcp://0.0.0.0:8000
22:10:12 [Ворота 2 — въезд] подключение от 127.0.0.1:50912
22:10:12 [Ворота 2 — въезд] OPEN DOOR 1
22:10:12 [Ворота 2 — въезд] отключение 127.0.0.1:50912 (закрыто эмулятором)
22:10:12 [Ворота 2 — въезд] подключение от 127.0.0.1:50913
22:10:12 [Ворота 2 — въезд] TABLO 000002 «K631TX199»
```

Строка `OPEN DOOR N` — принята команда «Открыть» на реле N.
Строка `TABLO <координата> «текст»` — то, что ушло на табло.

У табло две строки, и на панели они показываются обе: верхняя — то, что
пришло командой `text` (координата начинается с `00`), нижняя — то, что
пришло командой `scrolText` (координата начинается с `08`).

Каждое `execute()` клиента открывает новое соединение, поэтому на один
проезд приходится 1 подключение на ворота и по одному на каждую команду
табло (обычно 3).

### Панель

`http://127.0.0.1:8080/cvs/mptemu` — счётчики открытий, текущее содержимое
табло, журнал кадров с hex параметров, ответом и временем обработки.
Страница обновляется каждые `live_refresh` секунд; `?live=0` отключает
автообновление.

### Панель по SSE

Модуль `eventsse` показывает то же состояние живой панелью без опроса:
браузер один раз открывает поток Server-Sent Events и получает только
изменения. `http://127.0.0.1:8080/cvs/eventsse` (см. `modules/eventsse/README.md`).

### JSON и лог

```
http://127.0.0.1:8080/cvs/mptemu/state
```

`application/cache/mptemu/commands.log` — то же самое текстом, удобно
смотреть через `Get-Content -Tail 30`.

## Режимы имитации

Панель, раздел «Режим имитации»:

| режим | что проверяет |
|---|---|
| задержка, мс | реакцию клиента на медленный ответ |
| код ответа 1..4 | ветку `if($mpt->result == 'Err')` в `gateControl` |
| не отвечать | зависание на таймауте `SO_RCVTIMEO` |
| портить BCC | проверку контрольной суммы в `checkAnswer()` |
| рвать соединение | сценарий `'err'`, при котором сейчас пишется `HL_INSIDE` |

Режим действует на следующие принятые кадры, перезапуск не нужен.

## Почему ответ приходит быстро

`phpMPTtcp::sendCommand()` читает ответ в цикле `while ($out = socket_read(...))`,
то есть до закрытия соединения. Если соединение не закрыть, каждая команда
ждала бы `SO_RCVTIMEO` (3 с), и один проезд занимал бы ~12 с даже при живом
эмуляторе.

Поэтому эмулятор по умолчанию закрывает соединение сразу после ответа
(`close_after_response => TRUE` в конфиге). Клиент получает данные, затем
EOF, и цикл чтения завершается сразу. Замер на штатном клиенте:
`openGate` — 19 мс, команда табло — 20 мс.

Чтобы эмулировать устройство, которое держит соединение открытым (и тем
самым воспроизвести 3-секундные задержки клиента), поставьте
`'close_after_response' => FALSE`.

## Ограничения

- Задержка `delay_ms` блокирует цикл сервера целиком: для эмулятора это
  приемлемо, для многих одновременных клиентов — нет.
- `byte[1]` кадра ответа клиентом не проверяется; значение продублировано
  от `byte[2]` для совместимости с видом реальных ответов.
- Текст табло декодируется из `windows-1251`; если в `hl_messages` лежит
  UTF-8, на панели будет мусор — это признак неверной кодировки в БД,
  а не ошибки эмулятора.
- Панель, как и остальные страницы проекта, не требует авторизации.

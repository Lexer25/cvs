# eventsse — наблюдение за эмулятором mptemu через Server-Sent Events

Модуль повторяет идею `mptemu`, но результат отдаёт не опросом, а потоком
**Server-Sent Events**: панель один раз открывает `EventSource` и дальше
получает только изменения. Страница не перезагружается по таймеру и не
делает периодических запросов к серверу.

Эмулятор остаётся один — `mptemu`. `eventsse` не подменяет устройства, а
читает файл состояния `mptemu` и превращает его изменения в события:

```
mptemu (TCP-эмулятор)  ->  state.json  ->  eventsse  ->  EventSource  ->  браузер
```

## Состав

```
modules/eventsse/
  config/eventsse.php                  настройки потока
  classes/Eventsse/Hub.php             чтение состояния, diff, цикл SSE
  classes/Controller/Eventsse.php      панель, поток, JSON, управление
  views/eventsse/panel.php             разметка панели и клиент на EventSource
  README.md
```

## Включение

В `application/bootstrap.php` должны быть включены **оба** модуля, `mptemu`
раньше `eventsse`:

```php
'mptemu'   => MODPATH.'mptemu',
'eventsse' => MODPATH.'eventsse', // тот же эмулятор, но наблюдение через SSE
```

Без `mptemu` панель откроется с подсказкой, а поток отдаст событие `fatal`.

## Запуск

Эмулятор запускается как обычно:

```
C:\xampp\php\php.exe index.php --task=emulator
```

Отдельный процесс для `eventsse` не нужен: поток отдаёт Apache, на котором
работает сайт.

Панель: `http://127.0.0.1:8080/cvs/eventsse`

## Адреса

| адрес | что делает |
|---|---|
| `/cvs/eventsse` | живая панель |
| `/cvs/eventsse/stream` | поток `text/event-stream` |
| `/cvs/eventsse/state` | снимок состояния в JSON (`?feed=1` — с историей) |
| `/cvs/eventsse/mode` | POST: режим имитации комплекта |
| `/cvs/eventsse/clear` | POST: очистить табло комплекта |
| `/cvs/eventsse/reset` | POST: сбросить один комплект |
| `/cvs/eventsse/resetall` | POST: сбросить все комплекты |

## События потока

| событие | когда | полезная нагрузка |
|---|---|---|
| `snapshot` | сразу после подключения и после каждого переподключения | `{meta, devices, feed}` — полное состояние |
| `meta` | сменились `pid`, `started_at`, `alive` или версия | `meta` целиком |
| `device` | изменился комплект | `{host, alias, device, changes}`; `device = null` — комплект удалён |
| `command` | эмулятор принял новую команду | `{host, alias, records[]}` |
| `bye` | сервер закрыл поток по `max_seconds` | `{reason, retry_ms}` — браузер переподключится сам |
| `fatal` | поток не может работать | `{message}` |

События `meta`, `device` и `command` получают `id:` — порядковый номер в рамках
соединения. Повтор пропущенных событий сервер не делает: после
переподключения всегда приходит свежий `snapshot`, поэтому «дыр» в состоянии
не бывает.

Проверить поток из консоли:

```
curl.exe -N http://127.0.0.1:8080/cvs/eventsse/stream
```

Первые строки:

```
retry: 2000

event: snapshot
data: {"meta":{"ts":"09:20:11",...},"devices":{...},"feed":[...]}

: hb 1762000000

event: command
data: {"host":"127.0.0.2","alias":"Ворота 3.2 — въезд","records":[...]}
```

## Настройки (`config/eventsse.php`)

| параметр | по умолчанию | смысл |
|---|---|---|
| `state_file` | `NULL` | файл состояния; `NULL` — взять из `config/mptemu.php` |
| `poll_ms` | `250` | как часто сервер проверяет файл состояния (не браузер!) |
| `heartbeat_s` | `10` | комментарий-пульс, чтобы прокси не закрывали поток |
| `retry_ms` | `2000` | пауза перед автопереподключением `EventSource` |
| `max_seconds` | `300` | через сколько сервер вежливо закроет поток (`0` — никогда) |
| `replay` | `20` | сколько последних команд отдать в начальном `snapshot` |
| `feed_limit` | `100` | сколько строк держать в ленте на панели |
| `alive_check` | `TRUE` | проверять PID эмулятора через `tasklist` |
| `alive_every_s` | `10` | как часто перепроверять PID |
| `title` | `Живая панель событий` | заголовок панели |

`max_seconds` держим меньше `max_execution_time`, заданного в `.htaccess`
(`600`): поток закрывается сам, и браузер переподключается без ошибки.

## Панель

Матрица та же, что у `mptemu` (последняя команда, результат, время ответа,
счётчики реле, строки табло, режим, всего команд/ошибок, давность
подключения), плюс:

- индикатор потока: «подключение…», «поток подключён», «переподключение…»;
- счётчик полученных событий и время последнего;
- лента событий: команды появляются сверху и подсвечиваются;
- управление комплектами (режим имитации, очистка табло, сброс) уходит
  `POST`-запросом и сразу применяется; страница не перезагружается.

Всё, что показывает панель, приходит событиями: снимок встроен в страницу
при первом ответе, дальше обновляются только изменения. Единственный таймер
на странице — обновление надписей «5 с назад» раз в секунду; к серверу он не
обращается.

## Чем отличается от mptemu

| | mptemu | eventsse |
|---|---|---|
| транспорт | HTTP-ответ на запрос | `text/event-stream` |
| обновление панели | `location.reload()` каждые 3 с | push-события |
| нагрузка на сервер | постоянные запросы | одно соединение |
| что видит браузер | всю страницу заново | только изменения |
| история команд | перерисовывается таблицей | дописывается в ленту |

Панель `mptemu` продолжает работать как раньше и модулю не мешает.

## Ограничения

- Нужен `mptemu`: `eventsse` — только транспорт поверх него.
- Каждое SSE-соединение занимает поток Apache, пока открыто. Для панели
  наблюдателя это нормально; десятки одновременных подписчиков на
  `mod_php` лучше не открывать.
- `EventSource` есть во всех современных браузерах; в старом IE панель
  покажет сообщение и ссылку на `/cvs/eventsse/state`.
- В начальном `snapshot` команды разных комплектов упорядочены по `H:i:s`
  (дата в записях не хранится), поэтому порядок истории между комплектами
  приблизительный. Живые события приходят в точном порядке.
- `max_seconds` разрывает соединение по таймеру — это штатное
  переподключение, а не ошибка.
- Как и остальные страницы проекта, панель не требует авторизации.
